_The moment the Forth line stopped renting encoding from LLVM: WF65 makes a
hand-written Rust x86-64 encoder the default, and keeps LLVM only to prove it
byte-for-byte._

## TL;DR

- **What:** a complete, working 64-bit **STC Forth**, JIT-compiled via
  [JASM](/posts/jasm) — the version where the **native `Rasm` encoder becomes the
  default backend** and LLVM is demoted to an opt-in **differential oracle**.
- **Plus:** an **eager, rewind-and-replay peephole optimizer** (literal folding,
  `dup +` → `add rax,rax`, compare→branch, hot-variable `@`/`!` fusion).
- **Role:** short-lived as the tip (2026-06-08 → 06-10) — it was frozen to serve as
  the **correctness oracle** for its successor, [WF66](/posts/wf66).
- **Get it:** [Downloads](#download-run) · [Source](https://github.com/albanread/WF65)

## Where it sits

wf32 STC (Alex McDonald, 2020) → [WF64](/posts/wf64) → **WF65** →
[WF66](/posts/wf66) → [MF66](/posts/mf66) → [MF67](/posts/mf67). WF65 is the
LLVM-shedding hinge between the LLVM-hosted WF64 and the LLVM-free WF66. See the
[timeline](/timeline).

## What it is

WF65 keeps WF64's proven STC runtime substrate but swaps the encoding backend.
Its design note `docs/design/rasm-replace-llvm.md` states the new stance plainly:
**"NATIVE IS THE DEFAULT (2026-06)"** — the from-scratch `RasmEncoder` +
`NativeJit` (VirtualAlloc + relocations + W^X) is the working backend, and LLVM
(`--features llvm`) now "serves the differential **oracle** role: the only thing
that keeps `RasmEncoder` byte-honest." It ships both `wf64` (LLVM) and
`wf64-native` release builds.

## How it works

- **Native encoder default:** `RasmEncoder`/`NativeJit` emit and load x86-64
  directly; the LLVM-MC path is retained only to diff against, byte-for-byte.
- **Eager optimizer:** an emit-then-rewind/replay "replay substrate"
  (`LAST_LIT_*`, `OPT_FENCE`, `fold_*_comp`) rewrites the just-emitted code —
  literal/constant inlining, compare→branch, hot-var `@`/`!` fusion, `rdrop` inline.
- **Near-arena JIT:** runtime `CODE:` words are assembled into a near code arena
  (no trampoline), carried over from WF64.
- **Self-checking kernel:** the kernel inspects its own emitted bytes (leaf-inlining
  + peephole), so the native codegen must stay byte-compatible with the old LLVM
  path — which is exactly what the oracle enforces.
