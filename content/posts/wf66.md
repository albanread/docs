_WF65 optimized by emitting code and then rewriting it. WF66 optimizes the tokens
first, as data, and only then emits._

## TL;DR

- **What:** a token-IR optimizing **Forth**, successor to WF65 (a complete,
  working 64-bit STC Forth JIT-compiled via [JASM](/posts/jasm)).
- **The change in one line:** WF65 emits eagerly then *replays* (rewind +
  rewrite) to optimize; **WF66 captures each definition as a token IR, optimizes
  the tokens as data, and only then emits.**
- **Reuse:** keeps WF65's proven substrate — JASM/Rasm native encoding, the STC
  kernel primitives, the dictionary, the live REPL, the Rust test harness.
- **Get it:** [Downloads](#download-run) · [Source](https://github.com/albanread/WF66)

## Where it sits

The Forth lineage runs WF32 STC → WF64 → WF65 → **WF66** → [MF66](/posts/mf66) →
[MF67](/posts/mf67). WF66 is the compiler-architecture turning point that MF66
then carried onto Apple Silicon. See the [timeline](/timeline).

## What it is

> _From the README —_ "WF66 is the successor to **WF65**… It reuses WF65's proven
> runtime substrate… and **replaces the compiler**. WF66 captures each definition
> as a **token IR, optimizes the tokens as data**, and only then emits."

## Why I built it

- _Rewriting emitted machine code is fragile; optimizing an IR is not._
- _Keeping a known-good runtime while swapping the brain of the compiler._

## How it works

- **Token IR:** _how a definition becomes a token stream, what optimizations run
  over it (constant folding, stack-effect reasoning, peephole on tokens)._
- **Emit:** _tokens → JASM/Rasm native encoding → executable memory._
- **Inherited substrate:** STC kernel primitives, dictionary, live REPL.
